# البطاقات المتعلّمة — التخزين المحلي ثم قاعدة البيانات

هذا الملف للتعديل لاحقاً عند ربط لعبة **مطابقة الأصوات** بالخادم.
لا حاجة لتغيير شاشات اللعب إذا بقي شكل السجل كما هو.

## ماذا يُحفظ الآن؟

على الجهاز (AsyncStorage) بالمفتاح:

```
bayan:learnedCards:v1
```

عند ضغط الطفل **«أنا جاهز للتحدي!»** بعد شاشة التعلّم يُحفظ:

- `currentCardIds`: البطاقات الحالية المستخدمة في التحدي (مثل `cat`, `horse`)
- `sessions[]`: سجل كل جلسة تعلّم، جاهز للرفع

الصور وملفات الصوت **لا تُحفظ** في الذاكرة ولا تُرسل للداتا بيز.
تبقى في `CARD_DECK` داخل `app/(dashboard)/games/LevelThree.jsx`.
عند القراءة تُسترجع البطاقة الكاملة بالمعرّف عبر `hydrateLearnedCards`.

## شكل جلسة التعلّم

```json
{
  "schemaVersion": 1,
  "id": "lrn_....",
  "synced": false,
  "syncedAt": null,
  "createdAt": "2026-08-21T09:30:00.000Z",
  "patientId": 59,

  "cardIds": ["cat", "horse", "bell", "bird"],
  "cards": [

  ]

```

## الملفات المعنية

| ملف | الدور |
|---|---|
| `utils/learnedCardsStore.js` | القراءة / الكتابة / `syncUnsyncedLearnedCards` |
| `app/(dashboard)/games/LevelThree.jsx` | يستدعي الحفظ بعد التعلّم ويسترجع المجموعة عند فتح اللعبة |

## خطوات الربط مع الداتا بيز لاحقاً

### 1) جدول مقترح (SQL)

```sql
CREATE TABLE learned_card_sessions (
  id                BIGINT IDENTITY PRIMARY KEY,
  client_session_id NVARCHAR(64) UNIQUE NOT NULL,
  created_at        DATETIME2 NOT NULL,
  patient_id        INT NULL,
  patient_email     NVARCHAR(200) NULL
);

CREATE TABLE learned_card_items (
  id          BIGINT IDENTITY PRIMARY KEY,
  session_id  BIGINT NOT NULL REFERENCES learned_card_sessions(id),
  card_id     NVARCHAR(40) NOT NULL,  -- cat / horse / bell ...
  card_name   NVARCHAR(80) NULL
);
```

`card_id` يطابق `id` في `CARD_DECK`. لا تخزّن مسار الصورة في السيرفر إلا إذا أصبح عندك أصل بعيد (CDN).

### 2) مسار API مقترح

`POST /API/LearnedCards/Upload`

الجسم: مصفوفة من `toLearnedCardsApiPayload(session)`.

استخدم `client_session_id` لمنع تكرار نفس الجلسة.

### 3) تعديل واحد في المتجر — بدون تغيير اللعبة

في أي شاشة (مثلاً سجل المريض) أو بعد تسجيل الدخول:

```js
import {
  syncUnsyncedLearnedCards,
  toLearnedCardsApiPayload,
} from '../utils/learnedCardsStore'

await syncUnsyncedLearnedCards(async (pending) => {
  const res = await fetch('http://bayan.runasp.net/API/LearnedCards/Upload', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify(pending.map(toLearnedCardsApiPayload)),
  })
  if (!res.ok) throw new Error('upload failed')
})
```

إذا نجح الطلب تُعلَّم الجلسات `synced: true`. إذا فشل تبقى محلياً وتُعاد المحاولة.

### 4) ماذا لا تغيّره

- لا ترسل `require(...)` ولا ملفات mp3/png.
- لا تحفظ من داخل منطق الضغط على البطاقة في التحدي؛ الحفظ من طبقة `learnedCardsStore` فقط.
- أضف بطاقة جديدة في `CARD_DECK` بنفس `id` الثابت حتى تبقى السجلات القديمة صالحة.

## اختبار سريع

1. افتح مطابقة الأصوات → استكشف وتعلّم → أنا جاهز للتحدي.
2. أغلق التطبيق وافتحه مجدداً: تظهر أسماء البطاقات في الرئيسية («جاهز للتحدي: …»).
3. بعد توفر الـ API استدعِ `syncUnsyncedLearnedCards` كما فوق.
